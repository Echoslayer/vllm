## 重現步驟

先從上述 SHA 建立獨立工作目錄，不要在研究分支或正在進行其他修改的 checkout 執行。使用官方 [Apple CPU 安裝流程](https://github.com/vllm-project/vllm/blob/5d55ef1590c92213e3893dc8e8712f7f2e0bc508/docs/getting_started/installation/cpu.apple.inc.md)，並準備符合該頁條件的工具鏈。

下列命令從實跑 repo 根目錄開始。暫存路徑名稱與本次執行不同，但命令、套件來源與建置設定一致。

```bash
BASELINE_CACHE_DIR="$(mktemp -d)"
export UV_CACHE_DIR="$BASELINE_CACHE_DIR/uv"
uv venv --python 3.12 --seed --managed-python
uv pip install --python .venv/bin/python -r requirements/cpu.txt
MAX_JOBS=4 CMAKE_BUILD_PARALLEL_LEVEL=4 CARGO_BUILD_JOBS=4 \
  uv pip install --python .venv/bin/python -e .
uv pip install --python .venv/bin/python pytest tblib

export XDG_CACHE_HOME="$BASELINE_CACHE_DIR/runtime"
export HF_HOME="$XDG_CACHE_HOME/huggingface"
export VLLM_CACHE_ROOT="$XDG_CACHE_HOME/vllm"
.venv/bin/python -c 'import vllm; from vllm.platforms import current_platform; print(vllm.__version__); print(type(current_platform).__name__)'
.venv/bin/python -m pytest --collect-only -q \
  tests/multimodal/media/test_image.py::test_image_media_io_rgb_png_transparency
.venv/bin/python -m pytest -v \
  tests/multimodal/media/test_image.py::test_image_media_io_rgb_png_transparency
.venv/bin/python -m pytest -v \
  tests/multimodal/media/test_image.py \
  tests/multimodal/media/test_base.py
uv pip check --python .venv/bin/python
```

官方依賴檔包含未完全固定版本的套件，日後重跑可能解析成不同環境。先對照 [environment.json](T01-assets/environment.json)，不要把上方命令當成鎖定全部依賴的安裝腳本。

本輪使用一般 editable build 的隔離建置，沒有改用 `--no-build-isolation`，也沒有把平台偽裝成 CUDA。macOS 的 CPU 選擇由官方 setup 自動完成。

## 本次補到的實務細節

### 測試依賴不能直接照抄 Linux 清單

本次在官方 CPU 環境上，只額外安裝 `pytest` 與 `tblib`，就能正常收集並跑完上述兩個測試檔。這是這次快照與環境的實證，不是整套 vLLM 測試的最小依賴宣告。

沒有安裝完整 `requirements/test/cuda.in`。靜態查核發現它無平台條件地要求 `runai-model-streamer==0.17.1`；該版 PyPI 只有 Linux 發行檔，沒有 macOS wheel 或 sdist。這是選擇不安裝整份清單的依據，不是本輪實際執行 resolver 後得到的錯誤。[依賴清單](https://github.com/vllm-project/vllm/blob/5d55ef1590c92213e3893dc8e8712f7f2e0bc508/requirements/test/cuda.in)、[精確版本發行檔](https://pypi.org/project/runai-model-streamer/0.17.1/#files)

### Editable build 也處理 Rust frontend

建置過程曾在 `rustc -V` 等待數分鐘。之後單獨以 15 秒 timeout 執行同一命令，0.13 秒內成功；原建置接著進入 `cargo metadata` 與 `cargo build`。沒有修改工具鏈、停用安全設定或改動 vLLM，最後安裝成功。[版本查詢紀錄](T01-assets/validation.txt)

已確認產生 `vllm/_C.abi3.so` 與 `vllm/vllm-rs`；沒有測試 Rust HTTP 服務。等待原因沒有穩定重現，不能歸因於下載、系統掃描或 vLLM bug。專案確實指定 Rust 1.95，且 setup 會呼叫 Rust 建置；不能把整段安裝耗時都叫做 CPU C++ 編譯時間。[工具鏈設定](https://github.com/vllm-project/vllm/blob/5d55ef1590c92213e3893dc8e8712f7f2e0bc508/rust-toolchain.toml)、[建置入口](https://github.com/vllm-project/vllm/blob/5d55ef1590c92213e3893dc8e8712f7f2e0bc508/setup.py#L1704-L1716)

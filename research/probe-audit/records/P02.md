# P02：從編碼 helper 追到 parser 與 benchmark 輸入

**方向差異會保留到實際 parser 輸入，並非只存在於 base64 字串。** 同一張帶 EXIF 方向 6 的圖，直接 PIL 或原始 data URL 輸入得到 2×3；先經 `encode_image_url` 得到的 data URL 則為 3×2。同步與非同步 connector 結果相同。本輪沒有啟動 HTTP 服務或模型，不能據此聲稱推論準確率已受影響。

日期：2026-11-01。固定 SHA：`5d55ef1590c92213e3893dc8e8712f7f2e0bc508`；本輪重新 fetch 的 `upstream/main` 仍是此 SHA。環境沿用 [T01](../../tutorial-audit/records/T01.md)，Pillow 13.0.0。接續 [P01](P01.md)，產品程式與既有測試沒有修改。

## 實跑證據

`BOOK` 指向本研究書；在 T01 已安裝環境的工作區執行：

```bash
.venv/bin/python "$BOOK/research/probe-audit/records/P02-assets/probe.py"
.venv/bin/python "$BOOK/research/probe-audit/records/P02-assets/benchmark.py"
```

| 探測 | 實際呼叫 | 結果 |
| --- | --- | --- |
| 3 種來源 × 2 種輸出，共 6 組 | PNG RGB／RGBA、JPEG RGB → `encode_image_url` → `MediaConnector.fetch_image`／`fetch_image_async` → `MultiModalDataParser` | 原始 PIL 與原始 data URL 均為 2×3；編碼後 6 組均為 3×2，同步／非同步像素相同 |
| 只在編碼前加入正規化 | `ImageOps.exif_transpose` → 同一編碼與載入路徑 | 6 組尺寸恢復 2×3；PNG 輸出的 3 組像素也完全符合直接 PIL |
| benchmark 的 3 種輸入表示 | 同一 JPEG → `process_image` → connector | PIL、bytes dict 得到 3×2；原始 data URL 得到 2×3 |

來源：[路徑腳本](P02-assets/probe.py)、[6 組結果](P02-assets/results.json)、[benchmark 腳本](P02-assets/benchmark.py)、[3 種表示結果](P02-assets/benchmark-results.json)。每支腳本使用真實函式與斷言，無 mock、無模型下載。斷言鎖定目前的觀察；這些是研究探測，不是修好後應保持綠燈的回歸測試。

JPEG 有損重編碼可能改變像素，所以正規化後 JPEG 的 `pre_normalized_pixels_match=false` 不計為新增缺陷；這三組只以方向造成的寬高交換作判斷。RGBA 在本輪為完全不透明。方向 6 的尺寸訊號清楚，卻不能取代 P01 的全部方向矩陣。

## 預期行為與選題判斷

在目前一般路徑中，parser 與 bytes loader 都先正規化方向，因此「相同影像只換輸入表示，不應改變可見方向」有程式行為支持。不過編碼 helper 的 docstring 沒有承諾保存全部 metadata；保留 EXIF、把方向套到像素、或保留原始模型特定行為，是不同的設計決策。

[Mistral PR #62418](https://github.com/vllm-project/vllm/pull/62418)在本輪查核仍為 OPEN，head 為 `77a80e2f7d7aecea988d04f64b861305bbee72cf`。它要讓特定 tokenizer 路徑符合 `mistral_common` 的 EXIF 政策，不能把一般 parser 的結果當成所有模型的唯一契約。查重範圍沿用 [P01 搜尋紀錄](P01-assets/duplicates.md)；本輪只重查此相鄰 PR，沒有重新執行完整關鍵字搜尋。

已整理[中英候選卡 C01](../../../proposals/C01-image-orientation.md)，供下一輪決定修正範圍。建議先聚焦編碼 helper；benchmark 獨立分支保留為另外一項觀察，避免一開始擴成跨範例重構。候選卡尚未達到投稿條件，沒有對上游發文。

未驗證模型輸出、HTTP serving、GPU、真實資料集及其他 Pillow 版本。匯入時仍有 T01／P01 已記錄的 PyTorch 與 macOS FFmpeg/OpenCV 警告，兩支腳本均正常完成；沒有診斷那些環境警告。

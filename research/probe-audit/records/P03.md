# P03：Mistral 的兩種一致性，不能混為一談

**編碼前先轉正，不會在本輪探測中造成兩個解碼器不一致；但會改變 Mistral 相對於原始 bytes 所見的方向。** 因此不能把相鄰 PR #62418 當成否決「編碼前正規化」的理由，也不能只靠兩邊尺寸一致，就宣稱模型行為沒有變化。

日期：2026-11-02（Asia/Taipei）。vLLM SHA：`5d55ef1590c92213e3893dc8e8712f7f2e0bc508`；沿用 [T01](../../tutorial-audit/records/T01.md)環境，`mistral-common==1.13.0`、`Pillow==13.0.0`。產品沒有修改，沒有套用 #62418。

## 直接執行兩個解碼器

使用同一張 3×2、EXIF orientation=6、六種像素顏色的 RGB PNG。直接呼叫已安裝 `mistral_common.tokens.tokenizers.image.image_from_chunk` 與 vLLM `MediaConnector.fetch_image`，不以 Pillow 替身模擬 Mistral。

| 傳入內容 | mistral-common 尺寸 | vLLM 尺寸 | 兩者像素與尺寸相同？ |
| --- | --- | --- | --- |
| 保留原始 bytes 與 EXIF | 3×2 | 2×3 | 否 |
| 現有 `encode_image_url` 輸出 | 3×2 | 3×2 | 是 |
| 先 `exif_transpose` 再交給現有 helper | 2×3 | 2×3 | 是 |

[探測腳本](P03-assets/probe.py)及[完整結果](P03-assets/results.json)。在 T01 工作區執行，`BOOK` 指向研究書：

```bash
.venv/bin/python "$BOOK/research/probe-audit/records/P03-assets/probe.py"
```

腳本斷言三種策略的尺寸；像素相等另記入 JSON。它驗證現況與候選策略，不是產品修正的回歸測試。這裡的「保留原始 bytes」是控制組，並非已實作一個能涵蓋轉色與透明圖片的 metadata 保存補丁。

## #62418 實際要修什麼

本輪讀取 [PR #62418](https://github.com/vllm-project/vllm/pull/62418)的描述、一般留言及完整 diff。狀態仍是 OPEN，head `77a80e2f7d7aecea988d04f64b861305bbee72cf`；未讀取所有 inline review threads，不能把沒有看到反對意見當成維護者同意。

作者指出 Mistral chat template 與 vLLM 各自解碼同一圖片，原始 bytes 的方向處理不同會讓 token grid 不一致。PR 因此在使用 Mistral tokenizer 的 loader 與直接 PIL parser 路徑停用正規化，保留其他模型的預設行為。它沒有修改編碼 helper。

作者報告的 H100 HTTP 500→200、模型問答及效能結果，是作者的驗證，不是本書實跑。本輪只重現「原始 bytes 的兩個 decoder 尺寸不同」這個前提，沒有重現 HTTP 500、計算 token grid 或驗證該 PR。

已安裝 mistral-common 1.13.0 的 `tokens/tokenizers/image.py` 中，data URL 分支直接 `Image.open(BytesIO(image_data))`，沒有套用 EXIF transpose；本輪呼叫的就是這個函式。對應套件版本已記在 JSON，版本更新後須重查。

## 修正範圍的判斷

有兩個不同的目標：

1. **同一 payload 的解碼一致性**：chat template 與 vLLM 必須看到相同像素布局。候選預轉正策略在本輪符合這一點，不能因 #62418 就判定它一定不相容。
2. **換輸入表示後的語意一致性**：原始 bytes、直接 PIL 與 helper 產生的 data URL，是否應保留同一可見方向。一般 vLLM loader 的現況支持顯示方向，但 Mistral 的原始 bytes 行為採儲存方向。無條件預轉正會改變後者的內容，必須明確揭露與評估。

**本書的暫定選題建議**：C01 可繼續以「明確保存 helper 的可見方向」為候選，不新增模型偵測或設定旗標；下一輪在獨立實驗分支驗證最小 owner 修改與公開入口的 red／green 測試。若要正式投稿，必須明確描述方向改變，並補足受影響模型路徑的評估。這是研究建議，不代表維護者已接受此契約。

benchmark 的獨立 encoder 仍不納入初始修正，理由見 [P02](P02.md)。目前沒有產品補丁、上游發文或 PR，也沒有宣稱 C01 已可投稿。

## 限制

只實跑一種 RGB PNG、方向 6、data URL decoder；未跑完整 tokenizer、chat template、HTTP serving、模型推論、GPU、#62418 的測試或其他套件版本。原始 bytes 與候選編碼結果的模型語意差異仍未量測。匯入警告同 P01／P02，腳本正常結束。

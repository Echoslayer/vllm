# P01：PNG 編碼往返會失去 EXIF 方向嗎？

**已重現行為差異，尚未成為可投稿的修正。** 在 Pillow 13.0.0、預設 PNG 編碼下，帶 EXIF 方向 2–8 的 RGB、RGBA、LA 圖片經 `encode_image_base64` 再解碼，像素方向不同於直接載入原始 PNG。先正規化方向再編碼，這個小矩陣全部相符。尚未評估模型輸出、其他 Pillow 版本及實際服務請求。

日期：2026-11-01。vLLM 固定 SHA：`5d55ef1590c92213e3893dc8e8712f7f2e0bc508`。沿用 [T01 環境](../../tutorial-audit/records/T01-assets/environment.json)：Mac arm64、Python 3.12.12、Pillow 13.0.0。產品程式與既有測試沒有修改。

## 怎麼重現

在已依 [T01](../../tutorial-audit/records/T01.md)安裝的 vLLM 工作區執行；`BOOK` 指向本研究書工作區：

```bash
.venv/bin/python -m pytest -v tests/multimodal/test_image.py
.venv/bin/python "$BOOK/research/probe-audit/records/P01-assets/probe.py" > results.json
```

腳本只產生 3×2 或 3×1 的有效 PNG，不下載模型、不啟動服務、不修改產品。它以公開 `encode_image_base64` 和真實 `ImageMediaIO` 執行比較，未 mock 依賴。參見[腳本](P01-assets/probe.py)、[結果](P01-assets/results.json)及[既有測試日誌](P01-assets/existing-tests.txt)。

EXIF 矩陣的 alpha 為完全不透明；半透明只在第二個矩陣測試。數量是探索案例，不是新增 pytest 件數，也不是整個圖片模組的覆蓋率。既有測試的方向 3 案例只斷言尺寸，無法攔下同尺寸的翻轉差異。

## 如何縮小原因

先比較三種解釋：輸入沒有帶 EXIF、透明度合成丟掉 metadata、PNG 儲存沒有帶 EXIF。第一版探測未在 `save` 明確傳入 EXIF，重新開圖時並沒有方向標記，不能用來判斷產品。保存版本已明確寫入 EXIF，並斷言重新開圖仍有原方向；方向 5–8 的參照尺寸另有 2×3 斷言。

修正輸入後，RGB 也會失去方向，因此不能把原因只歸於透明度合成。結果 JSON 顯示全部編碼輸出的 EXIF orientation 都為空。只改變「編碼前是否正規化」這個條件，24 組就全部相符。這支持編碼路徑沒有保留顯示方向的判讀，尚不是對修正方式的定案。

固定來源與依據：

- [`ImageMediaIO.load_bytes` 與 `encode_base64`](https://github.com/vllm-project/vllm/blob/5d55ef1590c92213e3893dc8e8712f7f2e0bc508/vllm/multimodal/media/image.py)：載入先正規化再轉色；編碼轉色後直接 `save`。
- [`normalize_image` 與透明度合成](https://github.com/vllm-project/vllm/blob/5d55ef1590c92213e3893dc8e8712f7f2e0bc508/vllm/multimodal/image.py)：前者的註解要求像素符合顯示方向；後者建立新的 RGB 圖片。
- [`encode_image_base64`](https://github.com/vllm-project/vllm/blob/5d55ef1590c92213e3893dc8e8712f7f2e0bc508/vllm/multimodal/utils.py)：預設轉 RGB、編 PNG；文件沒有明確承諾保存所有 metadata。
- [Pillow `exif_transpose`](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html#PIL.ImageOps.exif_transpose)：依方向標記轉換像素並移除方向資料。本輪參照使用此 API，並未獨立驗證 Pillow 的全部轉換演算法。
- [Pillow 13.0.0 PNG writer](https://github.com/python-pillow/Pillow/blob/13.0.0/src/PIL/PngImagePlugin.py)：`_save` 從 `encoderinfo` 取得 EXIF；本機安裝原始碼也已核對。此結論不外推至其他版本或格式。
